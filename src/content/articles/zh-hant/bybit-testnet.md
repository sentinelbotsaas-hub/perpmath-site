59,660.0：2026-11-21 有三分鐘，Bybit 測試網上 BTCUSDT 的最新成交價就停在這個數字，一動也不動。我們在 17:27 到 17:31 UTC 之間讀了五次，每次都是它。同樣那三分鐘，真實市場印出來的是 60,230.2、60,256.4、60,243.5、60,268.9 和 60,133.5。測試網比它應該代表的市場低了 0.79% 到 1.01%，而且站著不動。

## Bybit 測試網是什麼？

它是交易所的第二份獨立副本，裡面跑的是練習資金。網站是 `testnet.bybit.com`，REST API 是 `https://api-testnet.bybit.com`（Bybit 的[串接指南](https://bybit-exchange.github.io/docs/v5/guide)，2026-11-22 查閱），兩者的帳戶、餘額和訂單都不跟 bybit.com 共用。在其中一邊開的帳戶，另一邊不存在。

Bybit 幫助中心那篇[測試網註冊說明](https://www.bybit.com/en/help-center/article/How-to-Request-Test-Coins-on-Testnet)（最後更新 2026-07-16，2026-11-22 查閱）稱它是正式網產品與服務的「100% replication」，也就是 100% 複製。先記住這個說法。對交易畫面和 API 來說，它接近事實。對價格來說不是，而且幫助中心的另一頁自己就這麼講。

### 怎麼註冊、怎麼領測試資金？

把測試網當成一間新的交易所來註冊，然後申請測試幣。照同一篇幫助中心文章的說法：

1. 用電腦上的瀏覽器開測試網網站，用電子郵件或手機號碼建立帳戶。文章說測試網只能從電腦瀏覽器進入。
2. 輸入寄到那個電子郵件或手機的驗證碼。
3. 到 Assets，再到 Assets Overview，然後按 Request Test Coins 並確認。

文章說每次申請會在現貨帳戶入帳 10,000 USDT 和 1 BTC，每 24 小時可以申請一次。它附了一個值得再講一遍的警告：絕對不要把真的幣轉到測試網的入金地址。文章說這種入金會永久遺失，測試網的提領也不會被處理。

API 這邊，接下來要在測試網網站上自己建立金鑰；串接指南要你到各站自己的 API 管理頁去建。正式網的金鑰不能用。Bybit 的[錯誤清單](https://bybit-exchange.github.io/docs/v5/error)（2026-11-22 查閱）在代碼 `10003` 底下寫明金鑰和網域必須對應，並列出四個環境：正式網、測試網，以及兩者各自的 demo 版本。金鑰只給合約交易權限，不要開提領或轉帳。理由，還有回報金鑰權限的那個端點，寫在 [Bybit API 那篇](/zh-hant/learn/bybit-api-python/)。

## 測試網和模擬交易（Demo Trading）：哪個是哪個？

兩個是不同的產品，價格來源也不同，名字卻老是被叫反。測試網是獨立的交易所，有自己的訂單簿。模擬交易是正式交易所裡的一個模式，餵的是真實價格，你的單是模擬出來的。

| | 測試網 | 模擬交易（Demo Trading） |
| --- | --- | --- |
| 在哪裡 | `testnet.bybit.com` | bybit.com 和 App 裡面 |
| 帳戶 | 另外註冊 | 正式網帳戶的一部分 |
| 練習資金 | 自己申請，每 24 小時一次 | 建立時入帳 |
| 價格 | 自己的訂單簿 | 跟著正式網 |
| 你的單會推動價格 | 會，在測試網的訂單簿裡 | 不會 |
| REST 主機 | `api-testnet.bybit.com` | `api-demo.bybit.com` |
| 功能 | 除了入金和提領以外都有 | 只有現貨和衍生性商品 |
| 進入方式 | 電腦瀏覽器 | 網頁和 App |

表裡各列出自 Bybit 的 [Demo Trading 說明](https://www.bybit.com/en/help-center/article/Demo-Trading)（最後更新 2026-10-30，2026-11-22 查閱）和 [demo trading API 頁面](https://bybit-exchange.github.io/docs/v5/demo)（2026-11-22 查閱）。模擬帳戶一開始有 50,000 USDT、50,000 USDC、1 BTC 和 1 ETH，它的單不會進真正的訂單簿。API 頁面說，demo 金鑰要在正式站切到 Demo Trading 模式時建立，demo 訂單保留 7 天。幫助中心另外寫到，模擬帳戶 30 天沒開就會被清空。

拆掉「100% 複製」的就是這一句：Demo Trading 那篇說明形容測試網的運作獨立於正式網價格，並提醒它不一定能準確反映真實的交易狀況。同一個幫助中心的兩頁，對測試網有多逼真說法不一；下面量到的數字站在第二頁那邊。

<!-- unique:firsthand-data -->
「價格」那一列我們自己驗了。2026-11-21 17:33 UTC，我們向正式網主機、demo 主機和測試網主機要同樣的 50 根已收盤 15 分鐘 K 線。demo 主機的 50 列和正式網完全相同。測試網的沒有一列對得上。

有一種組合要避開：測試網網站上也有一個 Demo Trading 模式。API 常見問題說不要用它，它會同時繼承兩邊的限制。

公開的成交紀錄還多透露一件事。正式網最近 1,000 筆成交涵蓋的時間是 14 到 68 秒，每次快照不同。測試網最近 1,000 筆每次都涵蓋 50 分鐘，穩定在每分鐘 19.8 到 19.9 筆。第一次快照裡，沒有任兩筆相隔超過 5.1 秒，而且 1,000 筆裡有 993 筆是買進千分之幾顆比特幣。下面是我的解讀，不是我能查證的事實：它看起來像一支腳本在維持成交紀錄不中斷，不像人在交易。這也說得通為什麼這麼冷清的市場裡，沒有任何一根 K 線缺漏或是空的。

Bybit 的 API 常見問題描述了實務上的後果。訂單簿缺少對手單時，測試網的市價單可能失敗，或在部分成交後被取消。那一頁沒有給保證有效的解法，建議改用限價單，或到正式站的 Demo Trading 這個流動性比較好的地方。後面會講到的下單程式，預設每單 100 USDT，在這個價位是 0.001 BTC，而我們五次快照裡最佳買價掛的量每次都比它多。

## 同一個策略，不同的 K 線：訊號會一樣嗎？

幾乎不會。機器人在測試網上讀的是測試網的 K 線，和讀真實市場的同一份程式碼會做出不同的決定。

<!-- unique:firsthand-data -->
我們從兩個主機下載同樣的 1,000 根 15 分鐘 K 線（2026-11-11 07:30 UTC 到 2026-11-21 17:30 UTC，兩邊都沒有缺），用開源引擎內建的三個範例策略、照它附的參數各跑一次。下表數的是進場訊號，以及有幾個落在同一根 K 線、同一個方向：

| 策略 | 正式網 K 線 | 測試網 K 線 | 同一根 |
| --- | --- | --- | --- |
| `ma_cross` | 16 | 22 | 0 |
| `fvg` | 42 | 96 | 3 |
| `liquidity_sweep` | 88 | 52 | 1 |

<!-- unique:original-calc -->
均線交叉在兩組資料裡從來沒有在同一根 K 線上發訊號；[公平價值缺口](/zh-hant/learn/fair-value-gap/)進場則是 134 根有訊號的 K 線裡只有 3 根重合。這些策略在測試網上跑出來不管賺還是賠，都是真實市場從沒給過的交易造成的。三個策略在引擎用正式網資料[公開的回測](/zh-hant/backtests/)裡都賠錢，[均線交叉](/zh-hant/backtests/ma-cross-btcusdt/)也不例外，這裡的結果改變不了那件事。

## 沒有金鑰，怎麼在測試網上測交易機器人？

從乾跑（dry run）開始，它只碰公開端點。引擎的下單程式（介紹在[機器人專區](/zh-hant/bot/)）有一個 `--dry-run` 參數：讀測試網的 K 線、跑策略、把原本要送出的訂單印出來。它建立 client 時不帶任何憑證，而 client 的簽章程式沒有憑證就拒絕執行，所以乾跑送不出簽章請求。

```text
perpmath live ma_cross --symbol BTCUSDT --interval 15m \
  --config configs/live/ma_cross.json --dry-run --once
```

下一步本來該是真的測試網金鑰和真的測試網訂單，而在這裡，老實交代現況比教學步驟重要。下單程式需要簽章的那條路（金鑰檢查、下單、掛停損、對帳）是用一個照文件寫的模擬 Bybit 伺服器測的，它的 [README](https://github.com/sentinelbotsaas-hub/perpmath/blob/85ee44e58a12eace4cd6645331d0d3ca74197da9/README.md#testnet-runner-02) 也這樣寫（commit `85ee44e`，2026-11-22 查閱）。它沒有用真的測試網金鑰下過單。我們沒親眼看過的下單流程，不打算寫。

還有一個限制：0.2 版只跟測試網主機講話，別的都不連。它拒絕正式網，也拒絕 Demo Trading 的主機，所以 Demo Trading 那些比較真實的價格，它目前碰不到。

## 測試網能驗證什麼，不能驗證什麼？

它驗的是管線通不通。凡是跟價格、成交量或其他交易者有關的事，它驗不了，理由就是上面那些數字。

| 問題 | 有答案嗎 | 為什麼 |
| --- | --- | --- |
| 我的簽章會被接受嗎？ | 有 | API 和簽章規則相同 |
| 金鑰的權限對嗎？ | 有 | 同一個金鑰資訊端點 |
| 訂單的數量和價格合法嗎？ | 大致上 | 最大下單量不同 |
| 程式重啟後撐得住嗎？ | 有 | 這是記帳，跟行情無關 |
| 熔斷機制會跳嗎？ | 有 | 練習資金的虧損照算 |
| 我會吃到多少滑價？ | 沒有 | 1 BTC 就讓訂單簿移動 1.44% |
| 我的單會成交嗎？ | 沒有 | 深度太淺 |
| 資金費會花多少？ | 沒有 | 90 次結算有 22 次貼在上下限 |
| 策略會賺錢嗎？ | 沒有 | 訊號和正式網不同 |

「大致上」要加個註腳。我們讀的時候，兩個網路的最小價格單位、最小數量和數量單位都相同，但限價單的最大允許數量在測試網是 1,190 BTC，正式網是 1,500；測試網上架的合約也少 11 個。重啟那一列同樣涵蓋逾時和重複的訂單 ID：那是訂單的記帳，價格怎麼走它都是同一套行為。

動筆的時候，我以為測試網是市場的一份雜訊多一點的副本，拿來粗略看看賺不賺還行。我錯了：比過 K 線，測試網上的損益我什麼用途都不會拿來用。在那裡賺了一整週，只說明機器人跑了一週。倉位大小和爆倉距離，請拿正式網的規則用[倉位大小計算機](/zh-hant/tools/position-size-calculator/)和[爆倉價計算機](/zh-hant/tools/liquidation-price-calculator/)來算；第一級風險限額在兩個網路上相同，300,000 USDT 以下維持保證金率 0.33%。

這次比較唯一排不出名次的是 Demo Trading。它的價格就是正式網的，訊號對不上的問題不存在。但那些不進訂單簿的單它怎麼撮合，我們沒有量過，Bybit 的頁面也沒有說明。

## 常見問題

### 正式網的 API 金鑰可以用在測試網嗎？

不行。金鑰只在發出它的那個環境有效，Bybit 的錯誤清單把金鑰和網域不對應列為 `10003` 的常見原因。我們送了一把編出來的金鑰到測試網，拿回來的就是這個代碼；請求和回應在 [API 那篇](/zh-hant/learn/bybit-api-python/)。

### 測機器人該用測試網還是模擬交易？

只是先確認下單、停損和重啟的行為，兩個都可以，而測試網開放的 API 比較多。只要跟真實價格有關，模擬交易比較接近，我們比對時它的 K 線和正式網完全相同。我們能示範的只有測試網，我們自己的下單程式就只支援這一個主機。

### 機器人在測試網有賺，上正式網也會賺嗎？

沒有理由這樣期待。在我們的樣本裡，測試網的收盤價和正式網的差距中位數是 1.87%，成交量是正式網的 0.68%，同一份策略程式碼在不同的 K 線上發出訊號。「在測試網有賺」，是在一個別處不存在的市場裡賺到的。
